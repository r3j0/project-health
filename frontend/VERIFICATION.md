## 2026-09-24: 성인 윗몸말아올리기 신규 등록 제거

프론트엔드 브랜치 `feat/frontend/fitness-onboarding`에서만 변경했다. 성인 간이측정의 근지구력은 교차 윗몸일으키기(60초)로 고정하고, 성인 `self_curl_up`을 직접 입력·사진 확인의 신규 입력 및 상세의 미입력 목록에서 제외했다. 공식 청소년 `curl_up`과 과거 저장 기록의 조회·수정은 유지한다. 백엔드 소스·카탈로그·스키마·API는 변경하지 않았다.

이전 간이측정 초안에 있던 윗몸말아올리기 횟수는 교차 윗몸일으키기로 재해석하지 않는다. 해당 임시 값만 제외하고 다른 측정값을 보존하며 안내를 표시한다. 기존 저장 요청의 결과가 미확정이면 원래 Idempotency-Key와 본문으로 확인한다. 공용 운동 실행기의 타이머·박자·수동 종료 기능은 재사용 가능하게 유지한다.

- `npm run check`: ESLint·TypeScript·단위 테스트 72개·프로덕션 빌드 통과.
- `npm run format:check`, `git diff --check` 통과.
- 최종 프로덕션 빌드에서 Playwright 22개 통과, 실패·건너뛰기·재시도 없음(36.1초).

- 모바일 준비 화면을 시각적으로 확인했다. `localhost:3000`을 최종 빌드로 갱신했다.

## 2026-09-24: 실제 백엔드 PR 연동 수정

프론트 `feat/frontend/fitness-onboarding`의 실행 코드 `0f43ffd` 기준이다. 실제 백엔드 PR #6의 `70fd83e159b6f8d4b738442f4d735c73c3038215`를 별도 체크아웃하여 연결했다. 이전 임시 백엔드 구현과 DB 스키마는 사용하지 않았다. Node.js 26.7.0 / Next.js 16.3.5 프로덕션 빌드 / Chromium 모바일 환경이다.

## 2026-09-22: 백엔드 연동 준비

작업 경로 `project-health-frontend-02`, 브랜치 `codex/frontend-phase-two`. Node.js 26.7.0 / Next.js 16.3.5 프로덕션 빌드 / Chromium 모바일 환경에서 확인했다. 백엔드 PR #6의 확인 시점 head는 `61d46b75a483655fb6618de6478412e4a43b9502`다.

### 구현 및 계약 경계

- 일반 운동과 간이측정 모드를 분리했다. 간이측정 저장은 기존 사용자 커리큘럼을 변경하지 않는다. 인증 만료 후 mode와 진행 중 입력을 복원한다.
- 사진 추출 API에 multipart 업로드·취소·오류/429·검토·수정·기존 API 저장을 연결했다. 사진 초안은 직접 입력 초안과 격리하며, 사용자가 확인 후 사진만 다시 선택할 수 있다. 저장 중·결과 불확실 상태에는 초안을 폐기하지 못한다.
- 서버 판정에 따라 6축을 항상 유지하고 원점까지 연결한다. 0/1/2개 평가, 기준 미달, 미입력/미지원 사유, 원본 결과표 등급 분리를 검증했다. 잘못된 id/revision/원본 값·단위/등급 응답은 차트로 표시하지 않는다.
- 회차별 상세 리포트와 메인·내 프로필의 최신 한 회차 대표 프로필을 연결했다. 저장·수정·삭제·다른 탭 변경·화면 복귀 이후 이전 차트가 남지 않는다.
- 평가와 대표 API의 URL·필드명은 **확정 전 제안**이다. 사진 추출만 현재 PR 명세를 사용한다. 상세 계약과 실제 연결 후 확인 항목은 [백엔드 연동 문서](BACKEND-INTEGRATION.md)에 있다.
- 이 브랜치의 `backend/`는 `origin/main`과 차이가 없다. 기존 백엔드 코드를 복구하거나 추가하지 않았다.

프론트 실행 코드 `2ffec35` 기준으로 최종 빌드를 새로 실행한 뒤 검사했다. 아래 결과는 이전의 부분 재실행 결과가 아니라 전체 회귀를 한 번에 실행한 결과다.

- 메인·내 프로필·상세 차트의 모바일 스크린샷을 확인했다. 320px 가로 넘침과 브라우저 실행 오류가 없었다. 원점으로 연결된 하나의 유효 축도 차트에 남는다.

### 회귀에서 확인하고 수정한 사항

1. 인증 복귀가 pathname만 사용해 간이측정 mode가 사라질 수 있었다. 허용한 로컬 경로만 복원하면서 assessment 쿼리를 유지한다.
2. 사진 미리보기가 접혀 있어 기존 확인 흐름과 달라졌다. 사진 선택 직후 원본이 보이게 복원했다.
3. 사진 확인 초안 복귀를 직접 입력 경로와 혼용하던 테스트를, 사진 전용 초안 자동 복원 흐름에 맞췄다. 재선택 시 직접 입력 초안은 유지한다.
4. 대규모 실제 인증 회귀 중 IP 요청 제한에 걸렸다. 제한을 낮추거나 해제하지 않고 15개 시나리오 단위로 시간창을 나눴으며 지연 응답·초안 보존 시나리오가 통과했다.
5. 대표 API가 상세 판정 항목 전체를 요구하지 않도록 요약 검증과 상세 검증을 분리했다. 대표 응답은 한 회차의 6축과 식별 정보만으로 연결할 수 있다.
6. 최신 백엔드 PR `61d46b7`은 사진 추출 요청 제한을 45초에서 75초로 늘렸다. 프론트의 50초 제한이 정상 응답을 먼저 취소하는 결함을 발견해 90초로 맞췄다. 코드·재현 회귀·연동 문서를 `2ffec35`에 커밋했다.

### 검증 한계

기존 실제 API 회귀는 이미 실행 중이던 전용 로컬 PostgreSQL과 이전 PR #6 사용자 API + 기존 간이측정 실험 지원 런타임을 사용했다. 현재 PR #6 head에 간이측정 저장 지원이 추가됐다는 뜻이 아니다. 새 사진 추출·평가·대표 프로필 브라우저 검증은 명시적인 HTTP 계약 대역을 사용하며 운영 경로에는 대역이 없다.

## 재현하여 수정한 문제

1. **운동 진행 되돌아감:** 기존 저장값이 있는 상태에서 저장소 쓰기가 실패하면, 최신 메모리 값보다 과거 저장값을 우선 읽었다. 최신 메모리를 기준으로 복원하도록 수정했다.
2. **폐기한 초안 재등장:** 저장소 삭제가 실패하면 로그아웃·초안 폐기 후 운동/측정 입력이 다시 복원될 수 있었다. 삭제 표시를 메모리에 유지하고, 저장소 삭제만 실패한 경우에는 빈 값으로도 덮어쓴다. 저장소 접근이 전부 막힌 환경의 보장은 같은 문서 안으로 한정된다.
3. **계정 변경 결과 불확실 시 복구 동선 부재:** 서버 변경은 성공했으나 브라우저 응답만 유실되면 재로그인 안내만 보였다. 중복 제출을 잠그고 `다시 로그인하기`를 제공한다. 선택 시 모든 탭의 로컬 인증·초안을 정리한다. 현재 비밀번호 오류는 자동 재전송하지 않으며 입력 수정 후 재시도할 수 있다.

회귀 테스트는 수정 전 실패를 확인한 뒤 추가했다. 탈퇴 응답 유실은 서버가 처리한 경우와 처리하지 않은 경우를 각각 검증하며, 재로그인이 실제 서버 결과를 따르고 탈퇴 요청이 반복되지 않는지 확인한다.

## 두 번째 검증에서 추가로 재현한 문제

기존 47개 E2E는 다시 모두 통과했지만, 추가한 세 시나리오는 수정 전 프로덕션 빌드에서 모두 실패했다.

- **저장 응답 유실:** 서버에 첫 측정 기록이 저장되어도 메인은 계속 미등록으로 안내했다.
- **마지막 기록 삭제 응답 유실:** 서버에서 기록이 삭제되어도 메인은 등록된 상태로 남았다.
- **화면 복귀 갱신 누락:** `visibilitychange`만 발생하고 `focus`가 없는 복귀에서는 다른 기기에서 만든 기록을 반영하지 않았다. 실제 기기를 대신해 브라우저 이벤트로 재현했다.

측정 변경 요청의 통신 오류·서버 오류에서도 같은 로그인 세션에 한해 `/auth/me`를 다시 조회한다. 등록 여부를 낙관적으로 바꾸거나 변경 요청을 자동 재전송하지 않는다. 기존 폼의 미확정 요청·중복 방지 키는 유지한다. 사용자 상태 공급자는 `focus`와 `visibilitychange` 모두에서 현재 화면이 보일 때 갱신한다.

추가 회귀 테스트는 `tests/e2e/phase-two-profile-recovery.spec.ts`에 있으며, 실제 서버 저장·삭제 후 브라우저 응답만 유실시키고 변경 요청이 한 번만 전송되는지 확인한다.
