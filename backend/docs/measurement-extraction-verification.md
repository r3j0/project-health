일부 기존 DB 경로에서 `pg` 드라이버의 동시 `client.query()` 사용에 관한 DeprecationWarning이 출력됐다. 현재 검사 실패는 아니며 린트 경고와는 별개다. 이 작업에서는 기존 Prisma/pg 동작을 변경하지 않았다.

## 실제 외부 호출과 남은 검증

**2026-09-21 최초 구현 검증에서는 실제 OpenAI API 호출을 수행하지 않았다.** 당시 작업 환경에 `OPENAI_API_KEY`·`OPENAI_OCR_MODEL` 설정이 없었고, 호출용 결과지 사진도 제공되지 않았다. 자동 테스트에서는 OpenAI transport를 테스트에서만 대체했다. 운영 코드에 테스트 대역·예시 성공 결과는 없다. 다음 날 수행한 실제 호출 결과는 아래에 별도로 기록한다.

남은 항목은 서버 키 주입, 실제 계정에서 이미지·Structured Outputs 지원 모델의 호출 권한 확인, 사용이 허용된 결과지 표본으로 [추출 curl 및 확인 후 저장 흐름](measurement-extraction-api.md)을 실행하는 것이다. 한글·작은 글자·기준표 혼동·다양한 센터 양식·사진 속 지시문에 대한 실제 모델 정확도는 이 자동 테스트의 보장 범위가 아니다.

## 2026-09-22 실제 사진 업로드·외부 API 검증

별도 로컬 테스트 DB에 임시 스키마를 만들고 기존 마이그레이션을 적용한 후, 실제 AppModule로 임시 HTTP 서버를 실행했다. 테스트 계정 생성과 Bearer 인증, `POST /api/v1/measurements/extract` multipart 업로드, 이미지 전처리, 실제 OpenAI Responses API, 서버의 카탈로그 검증을 모두 거쳤다. 사용 모델은 `gpt-5.6-terra`이며 transport 대역은 사용하지 않았다. 종료 시 테스트 스키마를 삭제했다.

이미지는 기존에 확보한 [ALIO 공개 첨부 문서](https://www.alio.go.kr/download/download.json?fileNo=3030277)의 개인정보 가림 예시 중 6쪽 체력평가 그래프와 7쪽 참고표를 그대로 사용했다. 원본 및 응답 JSON은 사용자에게 검증 증거를 제공하기 위한 로컬 `.local/live-extraction-2026-09-22/`에만 두며 Git에는 포함하지 않는다. 운영 API의 이미지 영구 미보관 정책은 유지한다.

| 입력                    | 실제 HTTP / OpenAI HTTP | 응답           | 측정값 / 검토 항목 | 소요 시간 |
| ----------------------- | ----------------------- | -------------- | ------------------ | --------- |
| 32×32 흰색 PNG          | 200 / 200               | `not_target`   | 0 / 0              | 3,315ms   |
| 7쪽 참고표 PNG          | 200 / 200               | `needs_review` | 0 / 0              | 8,616ms   |
| 6쪽 체력평가 그래프 PNG | 200 / 200               | `partial`      | 4 / 2              | 16,592ms  |

6쪽 사진의 SHA-256은 `947de3ee9dac76eefdcfe49ca830457aaac37ef77d860f1a3151fc3843b15e03`이다. API 반환 메타데이터는 측정일 `2025-10-14`, 센터 `서구(대전) 체력인증센터`, 종합등급 `3등급`이며, 가려진 나이·성별은 `null`이다. 다음은 모델이 반환하고 서버 형식 검증을 통과한 초안이며, 원본과 일치한다고 전부 확정한 정답 데이터가 아니다.

| code                     | value  | unit        |
| ------------------------ | ------ | ----------- |
| `relative_grip_strength` | `32`   | `%`         |
| `cross_sit_up`           | `24`   | `회`        |
| `step_test_vo2max`       | `26.4` | `ml/kg/min` |
| `sit_and_reach`          | `10.6` | `cm`        |

`reaction_time`과 `standing_long_jump`는 수치를 읽지 못해 `value: null` 및 `UNREADABLE_VALUE`로 검토 목록에 반환됐다. 항목별 원문 등급은 모두 `null`이었다. 실제 나이를 입력하고 원본을 확인해야 저장할 수 있다. `measurements`, `measurement_items`, `measurement_create_requests` 건수는 모든 호출 전후 각각 0이었으며, `isOnboarded`도 `false`로 유지됐다. DB 형식 JSON은 컬럼 매핑 예시이며 INSERT나 저장 API 호출 결과가 아니다.

검증 중 참고표 최초 호출은 기존 외부 호출 제한 30초에 걸려 `504 EXTRACTION_TIMEOUT`이었다. 전체 요청 제한을 75초, 외부 호출 제한을 60초로 조정했다. 참고표의 개인 측정결과 열과 등급 기준·평균 열을 구분하고, 메타데이터가 가려져도 보이는 후보를 반환하도록 프롬프트를 보완했다. **보완 후에도 7쪽 참고표의 수치 누락은 해소되지 않았다.** HTTP 성공과 스키마 검증 성공만으로 OCR 정확도 검증 완료라고 판단하지 않는다. 이번 검증은 6쪽에서 부분 추출 및 DB 미변경을 확인한 결과이며, 표본 확대와 작은 글자·참고표 정확도 개선이 남아 있다.

타임아웃 및 프롬프트 변경 후 단위 테스트 108개, 타입 인식 린트, 빌드가 통과했다. 위 182개 통합 테스트 전체 통과 기록은 9월 21일 구현 기준이며, 이번 실제 호출은 별도로 임시 PostgreSQL 스키마에서 수행했다.

## 2026-09-22 민첩성·순발력 누락 재검증

이전 응답은 두 검사를 호출 대상에서 제외한 것이 아니라 `reaction_time`과 `standing_long_jump`를 `reviewItems`의 판독 불가 항목으로 반환한 결과였다. 여섯 체력요인의 후보를 모두 처리하는 HTTP·카탈로그 경로에 네 항목 개수 제한은 없었다.

보완 사항은 원본 전체와 겹치는 네 구간의 상세 이미지를 동일한 한 번의 OpenAI 요청에 전달하고, 페이지 하단과 그래프 범례를 함께 확인하는 것이다. `detail: auto`로 GPT-5.6의 원본 해상도 정책을 사용한다. 구간별 확대는 최대 2배·긴 변 2,400픽셀, 준비 이미지 총량은 24 MiB로 제한하며 원본·상세 버퍼를 요청 종료 시 비운다. 작은 이미지에는 상세 이미지를 만들지 않는다. 업로드 계약은 여전히 이미지 한 장이며 DB 저장 계약은 변경하지 않았다.

동일한 공개 사진에 대해 최종 채택한 2배 상세 이미지 설정으로 두 번 호출한 실제 응답은 다음과 같다. 두 항목 모두 반환됐지만 민첩성 값이 일치하지 않았다. 테스트에서 육안으로 대조한 수치는 반응시간 `0.315초`, 제자리멀리뛰기 `159cm`이며, 이 수치를 운영 프롬프트·코드에 주입하거나 API 반환값을 보정하지 않았다.

| 요청                   | HTTP | items / reviewItems | reaction_time | standing_long_jump | 소요 시간 |
| ---------------------- | ---- | ------------------- | ------------- | ------------------ | --------- |
| `main-report-detail-1` | 200  | 5 / 1               | `0.715초`     | `159cm`            | 21,358ms  |
| `main-report-detail-2` | 200  | 5 / 1               | `0.315초`     | `159cm`            | 22,854ms  |

원본만 `auto`로 전달하는 대조에서는 기준 막대 수치를 본인 값으로 선택하는 오류도 있었다. 추가 비교한 3배 확대와 Terra의 `high` 추론 강도 역시 숫자 오독을 해소하지 못해 채택하지 않았다. 모델은 계속 `gpt-5.6-terra`이며 별도 추론 환경변수는 추가하지 않았다. 날짜, 스텝검사 값, 악력 단위·등급에서도 응답 간 차이가 관찰됐다. 앞선 네 항목 반환 기록도 정확한 정답으로 간주하면 안 된다.

**판정: 항목 반환은 개선됐지만 이 저해상도 표본의 OCR 정확도 검증은 실패했다.** API의 형식·단위 검증 통과는 사진의 숫자와 일치한다는 증거가 아니다. 추가 검증에는 더 선명한 원본과 대조 가능한 표본이 필요하다. 흰색 이미지에서는 계속 측정값 0건을 반환했고, 모든 시도에서 측정·항목·생성 요청 이력은 0건, 온보딩은 false로 유지됐다. 테스트 계정과 스키마는 종료 시 삭제됐다.

로컬 검증 자료는 `.local/live-extraction-2026-09-22/accuracy-comparison.json`에 대조 결과를, `main-report-detail-1-extraction-response.json`과 `main-report-detail-2-extraction-response.json`에 실제 응답을 보존한다. 실제 사진과 응답은 Git에 추가하지 않는다.

자동 회귀 검증에서는 구간 이미지의 모서리 누락 방지·크기 제한·취소, 단일 요청에 전체/상세 이미지 포함, 나이 미상 시 여섯 체력요인 보존을 확인했다. `npm run check`에서 단위 테스트 113개와 PostgreSQL 통합 테스트 183개, 총 296개 및 스키마·서식·린트·타입·빌드 검사가 통과했다. 자동 회귀 통과와 위 실사진 정확도 실패는 별개의 결과다.

## 2026-09-23 요청 중단·APNG 회귀 수정

검토 기준 `61d46b7`에서 HTTP 대기 종료와 이미지 작업 종료를 같은 것으로 취급해 슬롯을 조기에 반환하던 경로를 수정했다. 업로드·컨트롤러 처리 Promise의 실제 종료 시점에만 슬롯과 업로드 버퍼를 정리한다. HTTP 응답은 기존 요청 제한에 맞춰 종료하고, 미완료 업로드는 타임아웃 응답 전송 후 요청 스트림을 종료해 Multer가 정리를 마치도록 한다.

실행 환경은 Node.js 26.7.0, Sharp 0.35.4, libvips 8.18.6이다. 새 HTTP 회귀 테스트 4개는 실제 Nest 컨트롤러·인터셉터·서비스·Multer·Sharp와 로컬 HTTP 연결을 사용한다. 인증/호출 제한 Guard, 카탈로그 및 OpenAI client는 이 테스트에서만 대체한다. 실제 Sharp 상세 변환 결과를 만든 뒤 `.toBuffer()` Promise의 완료를 테스트에서 지연시켜, 취소 신호에도 즉시 끝나지 않는 작업을 재현한다. 네이티브 CPU 부하나 큐 길이를 측정한 테스트는 아니다.

- 네 요청의 상세 변환을 보류한 상태에서 각각 연결 종료 또는 요청 타임아웃을 발생시킨다. 타임아웃 응답은 변환을 풀기 전에 모두 504로 수신한다.
- 중단 이후 후속 요청 두 건이 모두 `503 EXTRACTION_BUSY`로 거절되고, 업로드·전처리 버퍼가 아직 비워지지 않았는지 확인한다.
- 지연한 변환을 성공 또는 실패로 종료하면 버퍼 정리가 끝나고, 새 요청이 200으로 처리되는지 확인한다. 중단된 작업은 외부 호출에 도달하지 않는다.
- multipart 본문을 끝내지 않은 업로드도 504 응답 후 슬롯이 회수되는지, 이미지 검증 실패 후에도 슬롯을 다시 사용할 수 있는지 확인한다.

합성 2×2·2프레임 APNG에서도 Sharp 0.35.4의 `metadata().pages`가 없고 단일 PNG로 디코딩되는 것을 직접 확인했다. [PNG Third Edition의 acTL 규격](https://www.w3.org/TR/png-3/#acTL-chunk)에 따라 실제 청크의 프레임 선언을 검사하도록 보완했다. APNG 거절, 잘못된 청크 길이·프레임 선언 거절, 텍스트/후행 데이터 오탐 방지 테스트 6개와 인증된 PostgreSQL E2E의 APNG 거절 사례 1개를 추가했다. fixture는 합성 이미지이며 개인정보를 포함하지 않는다.

최종 코드에서 `npm run check`가 종료 코드 0으로 통과했다. 단위·HTTP 회귀 테스트는 7개 파일 123개, PostgreSQL 통합 테스트는 10개 파일 184개로 총 307개다. 스키마 검증·Prisma 생성·서식·타입 인식 린트·타입 검사·빌드도 통과했다. 전용 테스트 DB에 임시 스키마를 만들고 7개 마이그레이션의 최초/재적용을 검사한 뒤 제거했다. 기존 `pg` 동시 `client.query()` DeprecationWarning은 계속 출력됐지만 검사 실패는 없었다.

이번 검증에는 실제 OpenAI 호출이나 실사진 정확도 재평가를 포함하지 않는다. 위 결과는 로컬 실행 결과이며 GitHub CI 통과를 의미하지 않는다. 이후 변경은 API 안내와 이 검증 기록의 문서화뿐이다.
