# API 버전 관리

현재 HTTP 계약 버전은 **v1**이며 기본 주소는 `http://localhost:3001/api/v1`이다. 인증·측정 카탈로그·측정 기록·상태 확인을 포함한 모든 API에 적용한다.

## 버전별 역할

| 대상                     | 관리 방법                                     | 변경 시점                            |
| ------------------------ | --------------------------------------------- | ------------------------------------ |
| HTTP 요청·응답 계약      | URL의 `/api/v1`, 향후 `/api/v2`               | 기존 클라이언트와 호환되지 않는 변경 |
| DB 테이블·컬럼·제약      | `prisma/migrations/`의 변경 이력              | DB 구조 변경                         |
| 측정 항목·단위·검증 기준 | `catalogVersion`                              | 검증된 검사 정의 변경                |
| 개별 측정 기록           | `revision`, `ETag`, `If-Match`                | 해당 기록 수정                       |
| 앱 배포물                | `package.json` 버전·Git 커밋 또는 릴리스 태그 | 배포 릴리스 정책에 따라 관리         |

URL의 v1은 서비스의 완성도나 DB 버전을 뜻하지 않는다. DB 컬럼을 추가했다고 API 버전을 자동으로 올리지 않는다. 현재 `package.json`의 `0.0.1`과 API v1은 서로 독립적이다. 응답마다 공통 `version: "v0.1"` 필드를 추가하지 않으며, 버전별 계약은 호출 URL로 선택한다.

## v1을 유지하는 변경과 v2가 필요한 변경

- 기존 요청의 의미와 결과를 유지하는 버그 수정, 선택 입력 추가, 새로운 API 추가는 v1에서 진행할 수 있다. 새 응답 필드도 기존 소비자가 허용하는지 확인한다.
- 기존 필드 삭제·이름 변경·자료형 변경, 선택 입력의 필수화, 단위·등급 의미 변경, 기존 클라이언트가 해석할 수 없는 응답 구조 변경에는 새 버전을 만든다.
- 데이터 팀의 알고리즘 버전은 계산 규칙 변경을 추적한다. HTTP 계약이 유지되는 알고리즘 변경만으로 HTTP 버전을 올릴 필요는 없다. 알고리즘 버전 저장은 추천 기능을 구현할 때 별도로 설계한다.

## 구현 방식

`src/config/api-version.ts`에 API 경로 접두사와 v1 상수를 정의한다. `configureApp()`은 NestJS의 URI versioning을 활성화하고, 각 Controller에 `version: API_V1`을 명시한다. 환경변수나 공통 최신 버전 값을 바꿔 기존 API의 의미를 일괄 변경하지 않는다.

v2가 필요하면 `API_V1`의 값을 바꾸지 않고 v2 상수와 컨트롤러를 추가한다. 호환되는 내부 로직은 서비스에서 공유할 수 있다. 새 버전의 인증·개인 정보 응답 캐시 금지·CORS·Location 경로·오류 계약도 함께 검증한다. 기존 소비자의 전환을 확인한 뒤 별도 종료 계획으로 v1을 제거한다.

근거: [NestJS URI versioning](https://docs.nestjs.com/techniques/versioning).

## 기존 로컬 호출 경로 전환

2026-09-19에 기존 `/api/...` 경로를 `/api/v1/...`로 전환했다. 예를 들어 회원가입은 `/api/v1/auth/register`, 상태 확인은 `/api/v1/health`다. 포트는 3001을 유지한다. 예전 버전 없는 경로와 아직 구현하지 않은 v2 경로는 404이며 자동 리다이렉트하지 않는다.

백엔드 문서·통합 테스트·더미 데이터 스크립트·생성 응답의 `Location` 헤더를 v1 경로로 변경했다. 외부 클라이언트, 프론트의 API base URL, 상태 확인 도구도 기본 경로를 `/api/v1`로 맞춰야 한다. DB 구조와 저장 데이터는 이번 변경으로 바뀌지 않는다.

## 검증

실제 PostgreSQL 통합 테스트에서 v1 인증·CRUD·토큰 갱신·로그아웃·CORS·캐시 금지·Location을 검증한다. 버전 없는 경로와 미지원 v2에 대해 등록된 13개 메서드·경로 조합이 모두 404인지 검사한다. 새 버전을 추가할 때는 해당 버전의 계약 테스트와 기존 버전의 회귀 테스트를 함께 유지한다.
