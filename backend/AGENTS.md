# Project Health 백엔드 개발 원칙

- 백엔드 코드·설정·문서·테스트는 모두 `backend/` 안에서 관리한다. 저장소 루트와 `frontend/`는 백엔드 작업으로 변경하지 않는다.
- User UPDATE는 이메일·비밀번호 같은 계정 정보 변경이다(2026-09-21 정정). 선호 운동·운동 목적·개인별 목표/기준값은 계획에서 폐기하며 `currentFitness` 프로필 응답도 제거한다. 기존 측정 CRUD·저장 기록과 ‘유효한 측정 1건 이상’ 온보딩 조건은 유지한다. User의 실제 컬럼은 `id`, `email`, `password`, `created_at`, `updated_at`이고 재화·커리큘럼은 별도 관계다. [계정 스키마](docs/account-schema.md)와 [사용자 API](docs/users-api.md)를 따른다.
- 실제 배포하고 운영할 웹앱을 개발한다.
- 원하는 화면이나 결과를 만들기 위해 사용자 데이터, 분석 점수, 추천, 완료 상태를 하드코딩하지 않는다. 운영 경로는 실제 입력·저장 데이터와 명시된 처리 규칙으로 동작해야 한다.
- 데이터가 없거나 외부 요청이 실패하면 그 상태를 반환한다. 예시 데이터나 임의의 성공 결과로 조용히 대체하지 않는다.
- 검사 코드·단위 같은 도메인 상수와 공식 기준 자료는 사용할 수 있다. 변경 가능한 기준에는 출처·확인일·버전을 기록하며, 미검증 기준으로 결과를 생성하지 않는다.
- 테스트 fixture와 개발용 예시 데이터는 운영 데이터·실제 사용자 결과와 분리한다.
- 측정 입력의 현재 범위와 결정은 [측정 데이터 명세](docs/measurement-data-spec.md)를 따른다. 국민체력100 결과 직접 입력과 부분 저장을 유지한다. 2026-09-21 사용자 결정으로 OpenAI 기반 사진 추출을 저장 전 초안으로 추가한다. 사용자 확인 후 기존 API로 저장하며 원본 사진은 영구 보관하지 않는다. [사진 추출 API](docs/measurement-extraction-api.md)를 따른다. 2026-09-23 사용자 결정으로 만 19–64세 간이측정(`self_assessment`) 저장·공식 종목 평가·6축 대표 조회를 포함한다. [평가 API](docs/measurement-evaluation-api.md)를 따른다. 커리큘럼 변경과 과거 기록 일괄 재평가는 범위 밖이다.
- 측정 지원 연령 확대는 MVP 이후에 진행한다. 현재는 만 13–64세 범위를 유지한다. 운동 영상 저장·조회, 추천 및 내부 가중치 갱신 연계는 현재 측정 데이터 단계 이후에 진행한다(2026-09-19 사용자 결정).
- 측정 HTTP 계약은 [측정 API 안내](docs/measurements-api.md)를 따른다. 인증된 본인 소유권, 생성 요청 키, 수정·삭제의 revision 조건, Decimal 문자열 정밀도를 유지한다.
- HTTP API는 [버전 관리 규칙](docs/api-versioning.md)에 따라 `/api/v1`에서 제공한다. 각 Controller에 버전을 명시하고, 기존 계약을 깨는 변경은 기존 버전 상수를 변경하지 않고 새 버전으로 추가한다.
- 기존 기획 문서와 최신 사용자 결정이 다르면 최신 결정을 반영하고 변경 근거를 문서에 남긴다.
- 2026-09-24 사용자 결정으로 공식 수치 기준을 확보하지 못한 성인 자가측정 `self_curl_up`을 신규 입력에서 제외한다. 기존 기록과 과거 카탈로그는 보존하며, 기존 항목의 유지·수정·제거만 허용한다. 별도 청소년 종목 `curl_up`은 유지한다. 최신 카탈로그는 `nfa100-2026-09-24`다.
